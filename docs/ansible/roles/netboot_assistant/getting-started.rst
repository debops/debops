Default configuration
---------------------

By default the role will download and prepare a set of Debian netboot
installers for various OS releases. The selection of the OS releases
corresponds to the list of Debian releases maintained in the iPXE boot menu
managed by the :ref:`debops.ipxe` role, as well as the Debian Preseed files
maintained by the :ref:`debops.preseed` role.


Support for non-free firmware
-----------------------------

The configured OS releases will include non-free firmware by default, to permit
easy installation of hardware hosts that might require it. This can be
controlled using a separate default variable or per OS release installation.

Only the "<release>" variants of the configured Debian releases will contain
the non-free firmware, the "<release>-gtk" variants don't work properly due to
the mismatch of the expected release names on the non-free firmware server.


Refresh script
--------------

The :ref:`debops.netboot_assistant` role will by default install a Python
script which will be activated by a :command:`systemd` timer at specific
intervals to update the installed netinst images. The script checks the
SHA256SUMS of the netinst tarballs on the Debian mirrors, therefore it will be
activated only on specific Sundays (Debian point releases are scheduled on
Saturdays).

The role has a list of Debian release dates which will be configured while they
are in the future; otherwise the script will be activated on the second Sunday
of each month to avoid frequent checks and minimize strain on Debian
infrastructure.


Additional useful services
--------------------------

The :ref:`debops.netboot_assistant` role relies on other DebOps roles to
provide the needed DHCP and TFTP services, as well as custom iPXE Boot Menu.
You can use either :ref:`debops.dnsmasq` on an internal network to configure
DHCP, DNS, PXE and TFTP services, or use :ref:`debops.dhcpd` and
:ref:`debops.tftpd` roles to set up a more comprehensive network environment.

The :ref:`debops.ipxe` role contains a customized Debian Installer menu which,
in conjunction with the Preseed configuration provided by the
:ref:`debops.preseed` role, allows for nearly automatic installation of hosts
and virtual machines over the network.


Example dnsmasq configuration
-----------------------------

With a TFTP server configured on host with 192.0.2.1/24 IP address, and the
TFTP root directory at :file:`/srv/tftp`, the role will maintain the set of OS
netinst images and a corresponding iPXE menu in the :file:`d-i/n-a/`
subdirectory of the TFTP root. To point the hosts and virtual machine to the
iPXE boot menu generated by the D-I Netboot Assistant service itself, you can
use the configuration below - an example for the :command:`dnsmasq` service:

.. code-block:: none

   # Definition of host types
   dhcp-match=set:ipxe,175
   dhcp-match=set:debian-installer,option:vendor-class,"d-i"
   dhcp-vendorclass=BIOS,PXEClient:Arch:00000
   dhcp-vendorclass=UEFI32,PXEClient:Arch:00006
   dhcp-vendorclass=UEFI,PXEClient:Arch:00007
   dhcp-vendorclass=UEFI64,PXEClient:Arch:00009

   # Network boot kernels installed by debops.ipxe role
   dhcp-boot=tag:!ipxe,tag:BIOS,ipxe/undionly.kpxe,,192.0.2.1
   dhcp-boot=tag:!ipxe,tag:UEFI32,i386-efi/ipxe.efi,,192.0.2.1
   dhcp-boot=tag:!ipxe,tag:UEFI,ipxe/ipxe-amd64.efi,,192.0.2.1
   dhcp-boot=tag:!ipxe,tag:UEFI64,ipxe/ipxe-amd64.efi,,192.0.2.1

   # D-I Netboot Assistant Boot Menu
   dhcp-boot=d-i/n-a/menu.ipxe,,192.0.2.1

The hosts will look for the :file:`d-i/n-a/menu.ipxe` file on the specified
host. This menu is also accessible via much more comprehensive Boot Menu
maintained in the :ref:`debops.ipxe` role.


Example inventory
-----------------

To configure D-I Netboot Assistant on a given host, you need to include in the
``[debops_service_netboot_assistant]`` Ansible inventory group:

.. code-block:: none

   [debops_service_netboot_assistant]
   hostname

If you are using the :ref:`debops.dnsmasq` role to provide DHCP and TFTP
services, the role will use its TFTP root directory to deploy and manage the
netboot images. Alternatively, :ref:`debops.tftpd` role can be used to provide
TFTP service on a separate host on the network, which is then specified via
DHCP as the "next server" for other hosts to boot from. The
:ref:`debops.netboot_assistant` role configured on the same host will use the
:ref:`debops.tftpd` role TFTP root directory as well.

Role entry points
-----------------

The ``debops.netboot_assistant`` role supports multiple entry points, utilized
by the playbooks provided with the role:

``service/netboot_assistant``
  The main playbook which configures a complete service stack using other
  DebOps roles as needed. Tags can be used to apply specific roles or exclude
  roles that are not needed in a given Ansible playbook run.

  This playbook is included in the main DebOps :file:`site.yml` playbook.

``scope/netboot_assistant``
  The playbook that only configures the D-I Netboot Assistant service itself.


Ansible tags
------------

You can use Ansible ``--tags`` or ``--skip-tags`` parameters to limit what
tasks are performed during Ansible run. This can be used after a host was first
configured to speed up playbook execution, when you are sure that most of the
configuration is already in the desired state.

Available role tags:

``role::netboot_assistant``
  Main role tag, should be used in the playbook to execute all of the role
  tasks as well as role dependencies.
